# 本文方法：第32版结构重新训练

`faultcrafter.method_model.MethodGenerator` 保留第32版的双分支、局部注意力、低秩路由、正常锚定故障组合和幅值建模结构。实验用七类工况量与七个存在掩码，保留PU扭矩和BJTU电驱频率等字段；电驱频率不解释为机械轴频。该模型不加载全数据发布权重。

每个T1共享底座、每个T2 LoRA适配、全参数微调或从零训练，最多5000次优化器更新。每个完整训练轮对设备／通道／状态／源工况单元各采一次，轮内统一长度512–16384，单批最多32段、65536点；下一完整轮超过剩余额度时停止。因此实际更新数可能小于5000。源验证固定随机数和16个长度，至少间隔500次更新，在完整轮结束后评价；2500次更新后开始选模，连续四次无0.1%的相对改善可提前停止。源验证与目标测试分离。

T2只继承同种子、指定HDU留出任务重新训练的共享底座。LoRA只更新新设备通道路由的低秩参数和新设备故障标签的嵌入行；新标签由同语义组的原设备标签均值初始化。每次优化和EMA更新后恢复所有旧行与共享参数，避免AdamW权重衰减改变冻结部分。原设备参数必须逐元素不变，加载选中检查点后再校验。全参数微调更新整个底座；从零训练不继承底座。

正式生成每条完整51802点父段采用32次网络前向：31个Euler积分区间至t=0.95，最后一次预测干净信号；记录实际NFE。归一化在完整父段上执行，再按已确认的1024点窗口／819点步长裁窗。T3两个增强配额共享父段和窗口顺序，63窗为252窗的子集，不为T3/T4另训生成器。

先查看全矩阵：

```bash
python -m research.benchmarks.proposed_train --data-run ../faultcrafter-data --output outputs/retrained32 --plan-only
```

正式运行并保存日志：

```bash
set -o pipefail
mkdir -p outputs/retrained32
python -u -m research.benchmarks.proposed_train --data-run ../faultcrafter-data --output outputs/retrained32 --with-retention 2>&1 | tee -a outputs/retrained32/console.log
```

`--scope proposed`只训练本文方法与非生成对照；`--scope external`只运行原外部矩阵；默认`all`包含两者。`--splits 42`用于单种子运行。`--job-id ID...`可选择已登记任务，自动补全生成器依赖；在另一张卡使用另一输出目录及不相交种子，可避免重复任务与检查点写入冲突。不要把单种子运行称为五种子完成。

开始前检查原始区间、内容别名和缓存窗口身份，失败即停止。正式目录的选择、数据、代码、父检查点或训练配置改变时拒绝续跑；检查点保存优化器、EMA、调度器、源样本顺序及随机数状态。`STOP_AFTER_CURRENT`在当前任务结束后停止；恢复前重命名该文件，再运行相同命令。

核心短验证使用独立目录并标记`verification_only`，不能向正式诊断入口提供检查点。旧受控U-Net短流程仍是独立参考实验，不自动视作本文方法的模型消融；阻尼冲击、长度分析等尚需接入正式方法，不能从空结果中推断完成。
